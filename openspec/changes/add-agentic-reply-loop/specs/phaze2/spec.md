## ADDED Requirements

### Requirement: Agentic Reply

The service SHALL reply to any incoming text message with a response generated by a LangChain built-in agent loop backed by the configured language model. The agent SHALL be constructed once using a built-in LangChain agent construct with no tools, and the message handler SHALL run the agent for the incoming text and reply with the model's answer. The handler SHALL remain modelled as an Effect and executed on the service's Effect runtime.

#### Scenario: User sends a text message

- **WHEN** a user sends any text message to the bot
- **THEN** the service runs the agent loop with that message and replies in the same chat with the model-generated answer

#### Scenario: Reply targets the originating chat

- **WHEN** the bot replies to an incoming message
- **THEN** the generated reply is delivered to the chat from which the message originated

#### Scenario: Model call fails

- **WHEN** the language model request fails or returns no content
- **THEN** the failure is reported via `Effect.logError`, the bot replies with a graceful fallback message, and long-polling continues uninterrupted

### Requirement: LLM Provider Configuration

The service SHALL read the language model provider API key from configuration via Effect's `Config` as a redacted value, and MUST fail to start with a clear error when the key is missing. The key MUST NOT be logged.

#### Scenario: API key provided

- **WHEN** the `GROQ_API_KEY` environment variable is set
- **THEN** the service uses it to authenticate the language model client and the value is never emitted to logs

#### Scenario: API key missing

- **WHEN** the `GROQ_API_KEY` environment variable is not set
- **THEN** the service fails to start and reports a clear configuration error indicating the missing key

### Requirement: Language Model Service

The language model SHALL be provided as a scoped Effect service constructed from the configured API key and a single configured model identifier. The service SHALL expose an Effect-returning operation that accepts a user message and yields the generated reply text, and it SHALL be provided to the application through the Effect layer alongside the Telegram bot service.

#### Scenario: Service constructed at startup

- **WHEN** the application layer is built with a valid API key
- **THEN** the language model service and its agent are constructed once and made available to the Telegram bot service

#### Scenario: Generating a reply

- **WHEN** the Telegram bot service invokes the language model service's operation with a user message
- **THEN** the operation returns an Effect that produces the model-generated reply text

## REMOVED Requirements

### Requirement: Static Text Reply

**Reason**: Replaced by the "Agentic Reply" requirement — the bot now generates responses via a LangChain agent loop instead of returning a fixed string.

**Migration**: No data migration. The static reply constant `hello` is removed; the text handler now calls the language model service to produce each reply.

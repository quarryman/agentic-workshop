## Why

The bot currently replies to every message with the static text `hello`, which is a placeholder. To make it useful we want it to actually answer users by running a LangChain agentic loop backed by a hosted LLM. Groq offers a free, fast, no-credit-card model tier, making it a low-friction first provider. This is the planned next step for which LangChain was pre-installed.

## What Changes

- Replace the static `hello` reply with an agentic response generated by a LangChain agent loop.
- Use a LangChain built-in agent/loop construct (no custom tools yet — a plain single-turn agent/model invocation over the user's message).
- Add the Groq chat model (`@langchain/groq`, `ChatGroq`) as the LLM backing the loop, selecting a free Groq-hosted model.
- Add an Effect `Config`-based read of `GROQ_API_KEY`, failing fast with a clear error when it is missing.
- Introduce the language model as an Effect service (constructed from the configured API key) so the bot depends on it via the Effect layer, consistent with the existing service-oriented design.
- The text-message handler runs the agent for the incoming message and replies with the model's answer (still modelled as an Effect, still Effect-logged).
- Update `.env.example` to include `GROQ_API_KEY`.

## Impact

- Modifies the Telegram text-message handler to invoke the agent instead of returning a constant.
- New runtime dependencies: `@langchain/groq` (Groq chat model) and `@langchain/langgraph` (for the built-in `createReactAgent` loop). LangChain core is already installed.
- New required environment variable: `GROQ_API_KEY` (in addition to `TELEGRAM_BOT_TOKEN`).
- New Effect service (e.g. `ChatModel`) wired into the application layer alongside `TelegramBot`.
- No webhook, persistence, or tool-calling changes — single-turn agent only.
